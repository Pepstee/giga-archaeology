# Engineering Doctrine Protocol

*Version 2.1 — 2026-08-29. Canonical domain owners, derived runtime copies, no personal profile.*

## Canonical domain owners

- `CONTEXT.md` owns settled engineering doctrine.
- `CHARTER.md` owns communication and collaboration preferences.
- `AGENTS.md` owns operational priorities and agent procedure.
- `00_MASTER.md` owns programme sequencing and status.
- An active numbered brief owns only the admitted scope of its exact workstream.

Personal or relationship context, travel state, project status, memories, and evidence do not
belong in engineering doctrine.

## Amendment rule

- A direct operator amendment changes the canonical owner for its domain first and is effective
  immediately there.
- An assistant-proposed amendment requires evidence and explicit operator ratification.
- Settled doctrine is not copied into unrelated planning or status files. Those files link here.
- Historical doctrine remains recoverable through Git history; obsolete clauses are removed from
  live guidance rather than kept active for sentiment or provenance.
- A derived runtime or deployment payload never originates an amendment. Change the canonical owner
  and regenerate the payload instead of editing its derived body.

## Derived copies

Runtime-specific and deployment-specific payloads are generated condensations, never independent
sources. After an applicable canonical amendment:

1. update the correct canonical domain owner;
2. update or regenerate each tracked deployment payload;
3. verify that no removed doctrine remains and no new doctrine was introduced;
4. record which live surfaces were actually redeployed.

An unverified or stale deployment copy must say so. It cannot overrule any canonical owner.

## Verification

A doctrine deployment passes only when it preserves the canonical decisions, omits private context,
contains no superseded clause, and does not broaden authority. Hash or semantic comparison should be
automated where the destination permits it; a prose claim of alignment is insufficient.
