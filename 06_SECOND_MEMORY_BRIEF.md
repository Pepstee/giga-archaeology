# Session 06 — The Second Memory (Jarvis)

*Read `00_MASTER.md` first. Mission: Artiom's second memory — a knowledge bank he throws raw
ideas and questions at, which files them correctly, produces connections he hasn't made, and
reminds him of things it has grounds to believe he needs. The skeleton already EXISTS and is
live (`memory/` — protocol, index, seed entries); this session's job is to deepen it into a
daily instrument, not to design it from scratch.*

## What exists (do not rebuild)

`memory/MEMORY_PROTOCOL.md` — the librarian duties (FILE, COLLIDE, REMIND), entry format,
laws (never delete; challenge contradictions; no secrets; weekly sweep; v3-consumption seam).
Three seed entries + `INDEX.md`. The pattern is deliberately his own proven one (orchestrator
KB / Cowork memory): markdown + frontmatter + index, LLM as librarian, no database, no
embeddings until keyword recall measurably fails (his N5).

## This session's deliverables

1. **Seed the memory properly** — an intake interview: standing decisions beyond the
   orchestrator, active questions he's chewing on, people/commitments worth remembering,
   ideas currently living only in his head. Target 20–40 real entries, each COLLIDE-checked
   as filed (the librarian behaviour demonstrated live, not described).
2. **The capture habit** — decide his lowest-friction inbox and wire it: a standing "Jarvis"
   Cowork chat pointed at this folder is the baseline; assess whether his Telegram
   orchestrator channel or a notes-file drop should ALSO feed it (if so, a sweep step that
   ingests the inbox into entries — capture must survive laziness, the ledger lesson).
3. **The weekly sweep, scheduled** — a scheduled task that runs the sweep from the protocol
   (due reminders; one non-obvious connection between recent and dormant entries; stale-active
   proposals; ≤10-line report). If Session 03's morning brief exists, the sweep output feeds
   it — one surface, not two.
4. **The synthesis test (the "thinking I haven't had" bar)** — before closing: ask the
   librarian three real questions against the seeded memory and judge whether at least one
   answer contains a connection or implication he genuinely hadn't formed. If not, tune the
   protocol's COLLIDE duty (more aggressive cross-linking, contradiction hunting) and retest.
   This is the session's acceptance criterion — a filing cabinet that doesn't think is not
   Jarvis.

## Boundaries

- The memory is the substrate for Sessions 02/03 (context = its identity tier; brief = its
  reminder surface) — coordinate, don't duplicate.
- v3 will eventually consume this folder (slices 14–16); never build a parallel store.
- Sensitive-data law applies with extra force here: this file set is his mind on disk.

## Done when

≥20 entries filed with collisions demonstrated; capture habit decided and wired; sweep
scheduled and run once; synthesis test passed; log + master table updated.
